5. スクリプトのカスタマイズガイド

配置・建物の形・色・光・市街の密度・カメラ経路を、どのファイルのどこを変えればよいかをまとめます。変更後は2章の手順で該当ステップから再実行してください。

どこを変えるか（早見表）

変えたいものファイル場所再実行するステップ
施設の位置・大きさdata/daidairi_layout_v3_1.csv各行の center_x_m 〜 size_y_mステップ1から
推定の建物を足す・消すdata/daidairi_conjectural_v1.csv行の追加、blockout 列を noステップ1から
建物の高さ・屋根・鴟尾scripts/build_chodoin_detailed.pybuild_detail() / build_detail_dairi()ステップ1から
色・質感scripts/build_chodoin_detailed.pyinit_materials()ステップ1から（GUIで直接変えても可）
太陽・空scripts/build_chodoin_detailed.pysetup_sky() と main() の Sunステップ1から（GUIで直接変えても可）
市街の密度・町並みscripts/build_city_layer.pyweights()、乱数の種 818ステップ2から
動画のカメラ経路・長さscripts/setup_axis_animation.pyKEYS、FPS、FRAME_ENDステップ3から
画質・解像度・速度各スクリプトの末尾samples、resolution_x/y、device該当ステップ

座標系の約束

  • 原点は朱雀門の中心。X＝東、Y＝北、Z＝上、単位はメートル。
  • 大内裏は Y＝0〜1394 付近、大極殿は Y≒565、市街は Y がマイナス側（南）に広がり、羅城門は Y＝−3850。
  • CSV の center_x_m, center_y_m は施設の中心、size_x_m, size_y_m は東西・南北の幅です。

1. 配置データ（CSV）を変える

配置の入力は data/daidairi_layout_v3_1.csv です。列の意味：

列意味
facility_id施設ID。スクリプトはこのIDで「どの部品で作るか」を決める（例：CHD_DAIGOKUDEN＝大極殿）
name和名。オブジェクト名の一部にもなる
typegate / hall / zone / enclosure / wall など。部品を持たない施設は、この種別で色付きの箱の高さが決まる
certainty史料確度 A〜D。生成には使わず、記録用（06_layout-coordinates.md 参照）
basis_note数値の根拠メモ
blockoutno にすると生成しない

例：大極殿を北へ10m動かす

CHD_DAIGOKUDEN の行の center_y_m に 10 を足すだけです。ただし回廊（build_chodoin_corridors()）や動画のカメラ経路は座標を直接持っているので、大きく動かす場合はそちらも合わせて調整してください。

Excel で CSV を開いて保存すると文字コードが Shift_JIS に変わり、スクリプトが読めなくなることがあります。VS Code など UTF-8 で保存できるエディタを使うか、Excel では「CSV UTF-8」形式で保存してください。

2. 推定レイヤーに建物を足す（いちばん簡単な追加方法）

data/daidairi_conjectural_v1.csv に行を足すと、IDごとの分岐を書かなくても type に応じた汎用部品で建物になります。生成物は COL_80_Conjectural コレクションに入り、属性 evidence=conjectural が付くので、根拠のあるデータと混ざりません。

type生成されるもの
hall殿舎（基壇＋白壁＋朱柱＋寄棟屋根）。幅24m以上なら基壇が高くなる
warehouse低い倉庫風の殿舎
compound_wall区画を囲む築地塀（南辺中央に開口）
office_compound汎用庁舎の充填＋築地塀
court_sand白砂の庭
facility_id,name,type,center_x_m,center_y_m,size_x_m,size_y_m,certainty,basis_note,blockout
CONJ_MY_HALL,試しの殿舎,hall,150,700,30,14,D,チュートリアルの例,yes

3. 建物の形を変える

建物は scripts/build_chodoin_detailed.py の部品関数で作られます。

関数作るもの主な引数
make_hall()殿舎roof_w, roof_d（軒先寸法）、kidan=(幅,奥行,高さ)、wall_h、roof_h、roof_mat、shibi（鴟尾の有無）
make_gate()門・楼w, d、upper（二重屋根）、passage（通り抜け開口）
add_hip_roof()反りのある寄棟屋根軒の高さ eave_z、屋根高 roof_h。反りの曲線は _roof_profile()
make_corridor_run()回廊の直線区間始点・終点の座標
infill_zone()官衙ゾーンの模式的な庁舎の並びstyle（office / warehouse / stable）

例：大極殿をさらに高くする

build_detail() の大極殿の分岐を探します。

    elif fid == "CHD_DAIGOKUDEN":
        make_hall("CHD_Daigokuden", cx, cy, 53, 26, col, fid,
                  kidan=(59, 24, 2.0), wall_h=9.0, roof_h=14.0,
                  roof_mat=MAT["roof_green"], shibi=True)

wall_h=9.0 を 11.0 に、roof_h=14.0 を 16.0 にすれば全高が約4m上がります。roof_mat=MAT["roof"] にすれば緑釉瓦から通常の瓦色に変わります。

新しいIDに専用の形を与える

  1. 配置CSVに行を追加する。
  2. IDを集合 DETAIL に追加する（入れないと色付きの箱になる）。
  3. build_detail() に elif fid == "新ID": の分岐を書き、部品関数を呼ぶ。
  4. 入れたいコレクションは main() の分岐（GATE_ なら COL_01、DAIRI_ なら COL_03…）で決まります。

4. 色と質感を変える

init_materials() に全マテリアルがまとまっています。make_mat(名前, 基本色, 粗さ, color2=まだらの色, tex_scale=まだらの細かさ, bump=凹凸) の形です。色は 0〜1 のリニアRGBです。

    MAT["vermilion"] = make_mat("MAT_Vermilion", (0.60, 0.10, 0.05), 0.55,
                                color2=(0.48, 0.07, 0.035), tex_scale=0.6, bump=0.05)

例：朱をもっと鮮やかにするなら基本色を (0.75, 0.12, 0.04) に。経年で褪せた朱なら (0.50, 0.18, 0.10) 程度に下げます。

試行錯誤は GUI のほうが速いです。生成済みの .blend を開き、Shading ワークスペースでマテリアル MAT_Vermilion の色を変えると、同じマテリアルを使う全建物に即座に反映されます。良い値が決まったらスクリプトに書き戻してください。

5. 光と空を変える

  • 太陽：main() 内の sun_data.energy = 3.2（明るさ）、sun_data.color（色）、sun.rotation_euler = (0.9, 0.2, 0.6)（向き。ラジアン）。夕景にするなら X 回転を 1.35 前後に倒し、色を (1.0, 0.7, 0.45) などに。
  • 空：setup_sky() の地平線色 mix.inputs[1] と天頂色 mix.inputs[2]、明るさ bg.inputs["Strength"]。
  • トーン：view_transform = "Filmic"、look = "Medium High Contrast"、exposure = 0.1。Blender 4.0 以降の既定である "AgX" にすると、彩度の高い朱が飛びにくくなります。

6. 市街の町並みを変える

scripts/build_city_layer.py は条坊の町（133m ピッチ）ごとに、確率で「貴族邸・官人宅・庶民町・寺・畑」を選んで作ります。

  • 密度：weights(side, band) の表。side が正なら左京（東）、負なら右京（西）。band は 0＝二条 … 6＝八条、−1＝宮の両側。各タプルは (貴族邸, 官人宅, 庶民町, 寺, 畑) の確率で、合計を1にします。
  • 別の町並みにする：rng = random.Random(818) の 818 を別の数にします。同じ数なら何度実行しても同じ町並みになります。
  • 区画ごとの建て方：build_plot() の kind ごとの分岐。
  • ランドマーク（羅城門・東寺・西寺・東西市・神泉苑）はスクリプト中に座標を直接書いています。data/heiankyo_city_landmarks_v1.csv は根拠の記録で、生成には読み込んでいません。動かす場合はスクリプトと SKIP_RECTS（町を作らない範囲）の両方を直してください。

市街は約1.5万オブジェクトあります。bpy.ops（primitive_cube_add など）で作ると極端に遅くなるため、このスクリプトでは fbox() / froof() など共有メッシュを使う高速関数を使っています。市街に部品を足すときも、この高速関数を使ってください。

7. 動画のカメラ経路を変える

scripts/setup_axis_animation.py の KEYS が経路です。1行が「フレーム番号、カメラ位置、注視点」です。

KEYS = [
    (1,   (0, -170, 3.0), (0, 0, 8)),      # 朱雀大路から朱雀門を見る
    (60,  (0, -45, 2.3),  (0, 180, 9)),
    (96,  (0, 5, 2.2),    (0, 250, 10)),   # 朱雀門をくぐる
    ...
    (288, (0, 445, 8.0),  (0, 565, 16)),   # 大極殿の前
]
  • 門の開口は地面から約1.0〜3.9mです。門を通過するフレームではカメラの Z を 2.2〜2.6 に保ってください（高すぎると屋根を突き抜けます）。
  • 長さを変えるなら FRAME_END と最後のキーのフレーム番号を合わせます。24fps なので 288 フレーム＝12秒。
  • GUI でカメラを動かしてキーを打つ方法は 4章を参照。

8. 画質・速度の調整

解像度scene.render.resolution_x, resolution_y動画 1920×1080、確認用 960×540
GPUscene.cycles.device = "GPU"事前にプリファレンスで OptiX/CUDA を有効にしておく（1章）
デノイズscene.cycles.use_denoising = TrueWindows 公式版には OpenImageDenoise が入っているので有効にできる。元の Linux 環境では使えなかったため既定は False
エンジンscene.render.engine = "BLENDER_EEVEE"リアルタイム系。動画の下書きを数分で作りたいとき

9. 開発のコツ

  • 出力先を分ける：環境変数 HEIAN_WORK を設定すると、v8・動画用 .blend・画像の出力先を切り替えられます（試作用と本番用を分けるのに便利）。 
    $env:HEIAN_WORK = "D:\heian_test"
  • GUI の中でスクリプトを試す：Scripting ワークスペースのテキストエディタでスクリプトを開き、Alt+P で実行できます。ただし build_chodoin_detailed.py はコマンドライン引数を前提にしているので、小さな試験コードで部品関数を呼ぶ形が扱いやすいです。
  • オブジェクトの属性：生成物には facility_id、evidence（conjectural / procedural_city）のカスタムプロパティが付いています。GUI のオブジェクトプロパティ → Custom Properties で確認でき、絞り込みや書き出し時の区別に使えます。
  • 根拠の記録：数値を変えたら、CSV の basis_note や 07_building-parts.md などの設計メモにも理由を残してください。このプロジェクトは「どこまでが根拠で、どこからが推定か」を分けて記録する方針です。
